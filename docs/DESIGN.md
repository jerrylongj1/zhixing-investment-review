# 知行 · 投资复盘工作台：设计规格

日期：2026-10-18。状态：待用户审阅；用户已认可产品方向及 Python 完整应用路线。

## 1. 目标与验收

在 24 小时题目约束内交付可操作的投资复盘应用。用户能够导入一次或一组交易，记录当时理由，查看按信息可得时间过滤的证据时间线，生成有引用的结构化复盘，并将学习保存为下一次决策清单。

验收交付：可访问的部署 URL、源代码仓库与 README、AI 使用与验证记录、测试说明。远程部署和代码仓库以实际成功结果为准；本地地址不冒充公开部署地址。外部服务缺少权限时明确记录阻塞。

## 2. 技术与产品选择

- 后端：Python FastAPI，Pydantic 校验，SQLite 持久化；数据库文件不进入仓库。
- 前端：React + TypeScript + Vite，中文响应式界面；生产构建由 FastAPI 同源提供，减少部署组件。
- 部署：提供 Dockerfile、环境变量示例与健康检查，适配支持 Python/Docker 的托管服务。Sites 的现有托管工作流不作为完整 Python 后端的替代。
- AI：通过服务端配置的模型 API 生成结构化复盘；未配置时提供明确标注的规则辅助复盘，不能显示为真实模型输出。模型失败显示失败状态，可由用户主动使用规则模式。
- 不实现券商交易、自动投资、收益预测、多人协作、生产级账户体系和付费功能。公开演示仅使用构造数据；真实交易默认在本地部署使用。公开部署若开放输入，则使用隔离的演示会话，不暴露其他用户记录。

## 3. 主链路与界面

界面采用深色侧栏、浅色工作区与清晰证据卡片，重点突出决策时点和信息边界。

1. 案例列表：进入构造样例、创建案例、选择一组决策。
2. 导入：下载 CSV 模板，上传交易；预览有效行与错误行，确认后写入。支持手动补充理由、记录时间、预期与失效条件。上传大小和行数设上限。
3. 证据工作台：选择决策及回看截止时点，按序展示交易、理由、行情和事件；切换“当时可知 / 全部后续”。证据抽屉展示原始字段、来源、时间、单位及口径。
4. 复盘报告：事实、归因假设、行为偏差线索、不确定性与过程改进分区呈现；每项引用可点开原始证据。结果质量与决策过程分开讨论。
5. 学习清单：从报告选择条目保存，支持编辑、勾选、持久化及 JSON/Markdown 导出；新建决策时可查看已有清单。

批量复盘只对选定决策聚合，保留每条结论的决策 ID 和证据 ID；不同标的、币种和缺少基准的数据不强行汇总收益。

## 4. 数据模型与时间语义

- Case：案例 ID、名称、构造数据标记、创建时间、会话归属。
- Decision / Trade：案例 ID、标的、交易方向、数量、价格、费用、币种、成交时间；理由单独保存原文、声称形成时间和实际记录时间。
- Evidence：证据 ID、标的、类型、事件发生时间、首次公开/可得时间、采集时间、来源、原文或原始字段、数值、单位、统计口径、质量状态及内容摘要校验值。
- Review：所选决策、截止时点、证据快照、生成模式、模型标识、结构化结论及验证结果。
- Checklist：条目、来源报告及引用、完成状态。

所有时间以带时区 ISO 8601 存储，界面使用 Asia/Shanghai。仅当 available_at 不晚于截止时点时，外部证据才可进入事前上下文。可得时间未知的证据列为“时点待核验”，不得当成事前已知。

历史理由若事后补写，显示“事后补录，无法证明当时已持有该理由”；不能只依赖用户填写的历史日期认定为事前记录。行情收盘值只在对应收盘后可得，不将当日完整 K 线提供给盘中决策。

## 5. 数据来源与失败处理

优先调查扶摇与 iFinD 的实际授权和文档。仅接入已验证的真实接口，不猜测端点或字段。提供数据适配器边界，将外部数据规范为 Evidence。无凭据时可导入带来源和可得时间的证据文件，并使用明确标记的构造行情及事件完成演示。

页面显示提供方状态、最后成功采集时间和失败原因。缺失、冲突、过期及超时均保留为质量问题；不自动用构造数据填补真实接口失败，不将“未发现”写成“未发生”。来源 URL 仅允许安全的 HTTP(S) 协议。

收益计算使用实际成交价格、方向、数量及费用；首版仅对可匹配的已实现交易展示已实现结果。无完整成本、不一致币种、缺少匹配买入等情形显示不可计算原因。价格涨跌和策略超额收益分别标注，不宣称实现了因果归因。

## 6. AI 约束与验证

AI 输入包括经过服务端时点过滤的证据和用户理由，用户内容及来源原文作为不可信数据处理。模型不能绕过时间过滤。报告采用固定结构，每条核心事实必须引用当前允许的证据 ID；未知引用、缺少引用或不符合结构的输出不作为正常报告保存。

事实与数值优先由程序提取和计算；模型提供有条件的解释。行为偏差仅作为线索，需引用行为证据，不因亏损自动判断错误，也不因盈利认定正确。归因不得声称已证明因果。不得输出确定性涨跌预测、收益承诺或直接买卖建议。异常输出拒绝展示正常结论，记录验证失败。

API Key 仅在服务端环境变量中读取，不返回浏览器，不写日志、提交或导出。导出不包含密钥和其他会话数据。AI 使用记录区分开发过程中使用的工具与产品运行时实际调用的模型；修正记录以真实发生的检查与修复为准。

## 7. API 边界

提供健康检查、案例创建与列表、交易预览/导入、决策读取与理由补充、证据导入/查询、报告生成/读取、清单增改与报告导出接口。所有案例资源校验归属；写操作校验请求体和长度；错误使用可识别代码与中文说明。文件不直接作为静态资源公开。

## 8. 验证与交付说明

- 主链路：样例及 CSV 导入 → 时点筛选 → 报告引用 → 清单保存 → 导出 → 重启后数据保留。
- 时点边界：恰好截止时点、跨时区、发布时间未知、事后补写、盘中使用当日收盘数据。
- 数据边界：空文件、非法时间、负数量、重复交易、未匹配卖出、费用、缺失来源/单位、冲突、接口超时和过期。
- AI 边界：未配置、API 失败、非法 JSON、伪造引用、无证据结论、提示注入、直接买卖建议。
- 隔离与安全：跨会话读取拒绝、超大输入拒绝、原文 HTML 转义、导出内容检查、密钥与隐私扫描。
- 前端：构建与类型检查，桌面/移动布局及关键交互的浏览器检查（以实际工具能力为准）。

README 记录启动方式、环境变量、产品选择、AI 角色、数据来源、部署步骤、已知边界及未做事项；测试说明记录实际命令、结果及未覆盖部分。
